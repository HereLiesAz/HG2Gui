# Lessons

## Judge generated frames against the user's intent, not only the prompt I wrote

- Cat tangent frame 13 (Persia): the prompt asked for abstract claw scratches with no legible characters. The user wanted cuneiform. I rejected the cuneiform render for breaking my own rule.
- Rule: when a prompt of mine constrains something the user never asked to constrain, a render that departs from it is a question for the user, not a rejection.
- Rule: say what a frame depicts and ask, rather than ruling it out, whenever the departure is a content choice (script, symbols, props) and not a defect (broken column, wrong colour, stray text).

## A requested rewrite means nothing carries over

- `top`: the user asked for a complete conceptual rewrite and rejected four pitches in a row (performance review, bed, stovetop, the first three alternatives), each of which kept workers, rankings or a literal reading of CPU use. The idea that worked was theirs: King of the Hill before the invention of the top.
- Rule: before pitching a replacement, list what the old version contained (characters, setting, props, joke) and drop every item. A pitch that keeps one is a revision, not a rewrite.
- Rule: when the user has stated a premise, execute it fully; do not re-pitch variants of it.
- Rule: when the user says an earlier prompt set "generates shit", the cause is usually too many objects and exact text in one image. Keep each frame to one idea and a few shapes, and use no lettering.

## Read the project's own reference frames before designing characters

- `05_top`: my first two cast designs (identical bean figures, then generic cream people) were rejected because they did not look like the Guide. The project's own frames in `docs/guide/project/references/shared/` already define the cast and style: tall paper-cut figures in uniforms, a woman with a megaphone, a big green bear in a blue coat, sound arcs and dashed arrows.
- Rule: before designing characters or props for any entry, open the existing reference frames and take the cast, proportions, palette and diagram language from them.
- Rule: when the user states a staging rule (here, "the camera must move, and we never see all the players"), treat it as part of the joke, not a detail. It changed the frames, the camera plan and the animation text.
